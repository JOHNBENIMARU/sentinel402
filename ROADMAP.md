# 🗺️ Sentinel402: R&D Roadmap (2024-2026)

Этот Roadmap определяет стратегический вектор развития проекта **Sentinel402**, основанный на передовых архитектурных паттернах Rust и актуальных трендах Web3.

---

## 🎯 Phase 1: Продвинутый AST и Безопасность (Q3 2026)
Фокус на усложнении детекторов для Odra/Casper с переходом от синтаксического к семантическому анализу.

- [ ] **Concurrency Detectors:** Анализ смарт-контрактов на предмет уязвимостей параллельного выполнения (State Locking, Race Conditions).
- [ ] **Data Flow Analysis:** Отслеживание изменения переменных от точки входа (Taint Analysis) для более глубокого поиска Reentrancy и неавторизованной записи.
- [ ] **Cross-Contract Graph:** Построение графа вызовов между несколькими контрактами в рамках одного скоупа (Workspaces).

## 🦀 Phase 2: Экспансия на Move DSL (Q4 2026 - R&D)
Адаптация архитектуры `sentinel402-server` для поддержки экосистем Sui и Aptos.

- [ ] **Move AST Integration:** Интеграция `tree-sitter-move` в наш модульный монолит.
- [ ] **Linear Types Analyzers:** Специфичные детекторы для экосистемы Move (проверки дропов ресурсов, неявного копирования, потери токенов).
- [ ] **Универсализация ядра:** Абстрагирование `Detector` trait, чтобы он принимал AST независимо от языка (Rust/Odra vs Move).

## 🧠 Phase 3: Client-side AI & WebGPU (Q1 2027 - R&D)
Сдвиг парадигмы в сторону децентрализованного выполнения.

- [ ] **WASM AST Engine:** Компиляция Rust-движка (парсинг и детекторы) в WebAssembly для запуска прямо в браузере (Zero-Backend Scan).
- [ ] **WebGPU LLM:** Эксперименты с запуском легковесных AI-моделей (например, Llama 3 8B q4 или специализированных секьюрити-моделей) локально через WebGPU/WebNN (MLC LLM).
- [ ] **Offline Mode:** Полностью автономный аудит без отправки кода на сервер.

## 🚀 Phase 4: Инфраструктурное масштабирование
- [ ] **Modular Monolith:** Окончательное разделение `server/src/engine`, `server/src/llm`, `server/src/mcp` на отдельные независимые крейты (crates) внутри `Cargo` workspace.
- [ ] **Actor Model Integration:** Переход на акторную модель (например, `tokio::sync::mpsc`) для асинхронной координации между AST-движком и LLM для параллельного сканирования десятков контрактов.
